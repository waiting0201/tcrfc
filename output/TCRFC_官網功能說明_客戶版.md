## 1. 網站是什麼

台中磐石足球俱樂部的官方網站，**繁體中文與英文雙語**，一套後台管理全部內容。

網站要同時服務四種人，每一種人進站的理由都不同：

| 來的人 | 想知道什麼 | 網站給他什麼 |
|---|---|---|
| **球迷** | 下一場什麼時候打、打得怎麼樣 | 賽事行事曆、賽果、球員名單、新聞 |
| **家長** | 小孩能不能來踢、怎麼報名、費用多少 | 學院介紹、課程與營隊、試訓報名 |
| **企業** | 贊助這支球隊能得到什麼 | 合作夥伴與贊助專區、提案簡介下載 |
| **媒體** | 要素材、要聯絡窗口 | 新聞與故事、媒體專區、聯絡表單 |

網站同時是**兩個俱樂部共用一套系統**的其中一站：台中磐石的官網是這一站，台中藍鯨女子隊有自己的獨立官網（另見《台中藍鯨官網功能說明（客戶版）》）。**兩站的內容分開、後台共用一個入口。**

## 3. 官方商店

商店**開在自己的網站裡**，不外連到第三方平台。收款主體是俱樂部。

**客人的流程**：逛商品 → 選規格（尺寸／顏色）→ 加入購物車 → 結帳 → **LINE Pay 付款** → 收到確認信 → 出貨通知 → 收貨。

| 項目 | 這一版怎麼做 |
|---|---|
| **付款方式** | **只有 LINE Pay** |
| **發票** | **一律開立電子發票**，可填載具、統編或捐贈碼 |
| **要不要註冊** | **不用**。非會員可以直接結帳，事後用訂單編號 ＋ Email 查詢 |
| **運費** | 固定運費 ＋ 免運門檻 |
| **賣什麼** | **只賣實體商品**。會籍、課程費、捐款都不走商店結帳 |
| **退換貨** | 站內申請，退貨時發票作廢或折讓 |

> **舊官網的 Wix 商店**在新站上線後停售，網址轉到新商店。

藍鯨的商品也在這套系統裡賣，**收款與發票抬頭仍是俱樂部**，事後依商品歸屬結算給藍鯨。購物車**一次只能買同一個俱樂部的商品**。

## 4. 會員與會員卡

會員系統**只做會籍這一件事**，分兩層：

| | 免費會員 | 付費會員（球迷會員） |
|---|---|---|
| 特約店家折扣 | ✔ | ✔（更好的折扣） |
| 球衣 | — | ✔ 一件 |
| 抽獎資格 | — | ✔ |
| 電子會員卡 | ✔ | ✔ |

**重點規則**：

- **一個人一組帳號，但會籍是每個俱樂部各一份。** 只加入磐石、只加入藍鯨、兩隊都加入，都是正常情況。
- **每一份會籍配一張電子會員卡**，卡面帶該俱樂部的標誌與品牌色。
- 店家收卡時掃 QR，開啟的驗證頁只顯示**姓名首字、會員編號、層級、有效或已過期**——不會洩漏個資。
- 會費採**球季制**，以 LINE Pay 收款連結或現場收款，不走商店結帳。
- **兩隊球季不同步**，到期日與續會提醒各自計算。

**抽獎**：付費會員在開獎的基準時間只要會籍有效就**自動具備資格，不需要任何操作**，一人一個號碼。**不會因為多消費、多簽到、多分享而增加中獎機會。** 實際開獎由人工在現場或直播進行，中獎名單以最新消息公布。

## 6. 誰能做什麼

後台採角色分工，**每個人只看得到自己該看的**。實務上會用到的是這六種：

| 角色 | 負責什麼 | 建議由誰擔任 |
|---|---|---|
| **系統管理員** | 全部功能，含帳號、金流設定與退款 | 一到兩人，不宜多 |
| **內容與公關** | 新聞、頁面、FAQ、媒體素材、商品文案 | 行銷或內容窗口 |
| **球隊與課程管理** | 球隊、球員、賽程、賽果、課程梯次、報名 | 教練團或行政 |
| **商務／贊助** | 合作夥伴、贊助方案、廣告 | 商務窗口 |
| **客服／行政** | 會員、會籍、訂單、出貨、退貨、報名處理 | 日常維運的主力 |
| **合作球隊管理** | 藍鯨方自己的內容、球隊、會籍與訂單 | 藍鯨方的維護人員 |

另有兩種輔助角色：**翻譯人員**（只能編輯英文欄位，改不到中文原文）與**檢視者**（唯讀，看不到金額），視實際分工再決定要不要開。

**三個保護機制**：

- **退款、金流設定與 App 版本發布只有系統管理員能做。** 這幾件事出錯不可逆，權限刻意收在最小範圍。
- **推播通知要兩個人。** 一個人撰寫，系統管理員核可後才會送出——推播是收不回來的全體觸及。
- **內容採「送審 → 發布」**，不是誰都能直接上線。

**個資的三條線**：

1. 會員的 Email、電話、生日、收件地址屬**受限資料**，只有系統管理員與客服／行政看得到完整值，其他角色看到的是遮罩過的（例如 `a***@gmail.com`）。
2. **名單匯出要另外授權**，而且每一次匯出都會留下紀錄：誰、何時、匯出幾筆、用途。
3. **抽獎名單視同會員個資**。公關寫公布稿時拿到的是遮罩版名單。

## 7. 上線後誰要持續維護什麼

網站不是上線就結束。下表是**實際的人力預期**，建議在上線前就把人指定好。

| 要維護的東西 | 多久一次 | 誰 | 不做會怎樣 |
|---|---|---|---|
| **賽程與賽果** | **賽季期間每週** | 球隊與課程管理 | 賽事行事曆是全站最常被看的內容，一延遲就直接傷到 |
| **新聞與故事** | 每週一到兩則 | 內容與公關 | 首頁會顯得停擺 |
| **球員與教練名單** | 每季，轉隊時隨時 | 球隊與課程管理 | 名單過期比沒有名單更糟 |
| **課程與梯次** | 每次開課 | 球隊與課程管理 | 家長看到的是舊梯次 |
| **報名收件處理** | **每日** | 客服／行政 | 家長等不到回覆就流失 |
| **商品與庫存** | 上新品與補貨時 | 商務／客服 | 超賣要人工善後 |
| **訂單與出貨** | **每日** | 客服／行政 | 出貨延遲直接變客訴 |
| **會籍開通與續會提醒** | 每日到每週 | 客服／行政 | **兩隊球季不同步，全年都會有到期案件** |
| **FAQ** | 每月 | 客服／行政 | 同樣的問題會一直進收件匣 |
| **英文版** | 跟著中文版 | 翻譯人員 | 英文版會逐漸落後成半殘狀態 |

> **最需要提前決定的是前三項的負責人。** 賽程、新聞、名單是球迷回訪的理由，也是三項**持續性**工作——不是做一次就結束。

## 8. 雙語

- **繁體中文為主，英文為輔**，網址以 `/zh/`、`/en/` 區隔。
- 所有前台看得到的內容都有中英兩個欄位，**英文可以先留空，但欄位一定存在**——不會發生「想加英文卻得改程式」的情況。
- 架構上已預留第三語系，日後要加日文或其他語言不必重做。
- 英文版落後時，該頁會顯示中文並標示語系，不會出現空白頁。
