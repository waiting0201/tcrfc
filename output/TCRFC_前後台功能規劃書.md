## 1. 專案目標與範圍

### 1.1 商業目標

| 目標 | 網站對應功能重點 |
|---|---|
| 打造世界級足球生態系網站 | 完整的一線隊／學院／女足／課程四大體系內容架構 |
| 提升品牌影響力 | 新聞故事系統、台中磐石文化（漫畫）、球迷俱樂部、官方商品 |
| 吸引人才（球員、教練、學員） | 招募／試訓／報名轉換漏斗、國際發展路徑（Pathways） |
| 拓展國際合作與贊助夥伴 | 合作夥伴專區、贊助方案、提案簡介下載、B2B 詢問表單 |

### 1.2 五大核心價值（貫穿全站視覺與內容標籤）

`Players First 以球員為本`、`Excellence 追求卓越`、`Global Pathways 國際發展`、`Community 社區共好`、`Integrity 誠信專業`

> 建議：核心價值作為**內容標籤**（Value Tag）存在後台，可標記於任何文章／球員故事／活動，前台可據此聚合展示。

### 1.3 系統範圍

- **前台（Public Site）**：13 大單元、約 60+ 子頁面、7 類 CTA 轉換表單、**會員中心**、**雙語系（繁中／英文）**。
- **後台（Admin CMS）**：內容管理、球隊與賽事管理、報名與名單管理、**會員管理**、FAQ 管理、慈善事蹟管理、表單詢問管理、商品與夥伴管理、SEO 與網站設定、權限與稽核。
- **不在本次範圍**：
  - **電商與金流** — 購物系統一律導往 **Shopify**，本站不建購物車、不接金流、不管訂單與庫存；官網僅維護商品櫥窗與導流連結（詳見 3.8 / 4.6）。
  - **技術選型** — 本文件為功能規格，不涉及框架、CMS、部署環境等技術決策。
  - 票務系統、會員點數與電子錢包（建議後續評估）。

### 2.1 頁面型態分類

| 型態 | 說明 | 後台管理方式 |
|---|---|---|
| **主頁 Main Page** | 首頁 | 版位模組化編排（Page Builder） |
| **主分類 Main Category** | 各主分類 Landing 頁 | 固定版型 + 可編輯區塊 |
| **子分類／子頁 Sub Page** | 2.1、3.1 等 | 固定版型 + 可編輯區塊 |
| **內容／項目頁 Content / Item Page** | 球員、教練、新聞、賽事、商品、漫畫集數 | 資料型 CRUD（列表 + 詳情） |
| **行動呼籲頁 CTA Page** | 10.x 各類表單、贊助提案下載 | 表單設計器 + 收件管理 |

### 2.2 全域導覽建議

- **主選單（Desktop）**：ABOUT / CLUB / ACADEMY / PROGRAMS / WOMEN'S / SCHEDULE / NEWS / CULTURE / PARTNERS / CHARITY，右側常駐 `JOIN 加入我們`（強調色按鈕）、`會員登入 / 會員中心`、語系切換 `繁中 / EN`。
- **Mega Menu**：每個主分類展開顯示第二層項目 + 一張主視覺圖 + 一個該分類主 CTA。女足與慈善為單層頁面，直接連結不展開。
- **行動版**：漢堡選單全屏抽屜（含語系與會員入口），底部固定 CTA Bar（`加入球隊` / `聯絡我們`）。
- **Footer**：站點地圖四欄（含 FAQ、慈善事蹟）、社群連結、贊助夥伴 Logo 輪播、Shopify 官方商店連結、聯絡資訊、隱私權／Cookie 政策、語系切換。

3. 選定隊別後，頁面標頭顯示：隊伍名稱、下一場賽事倒數；並提供該隊別**專屬的行事曆訂閱網址**（例：家長只訂閱 U12 賽程，不會收到 D1 賽程）。
4. 隊別清單由後台 C1 球隊資料自動產生，**日後新增梯隊（如 U18、U10）即自動出現於分類**，不需改程式（對應 4.2「其他年齡層」）。

> **名詞對照**：**D1 即 3.1 的 First Team 一線隊**，兩者為同一支球隊，並非另設隊伍。`D1` 為全站統一使用的**隊別代號**，用於行事曆分類、篩選標籤與訂閱網址；`First Team / 一線隊` 為對外顯示名稱，用於 03 FOOTBALL CLUB 各頁面標題與內文。
>
> 因此隊別清單（D1 / U15 / U14 / U12）= 一線隊 + 4.2 Our Teams 的三個梯隊，涵蓋俱樂部全部競技隊伍。

### 3.14 MEMBER 會員中心

**定位**：以會員身分串接「球迷會、課程報名、活動報名、電子報」四大既有場景，降低重複填表成本並累積名單資產。

#### 入會管道（三種並行）

| 管道 | 適用情境 | 說明 |
|---|---|---|
| **A. 官網 Email 註冊** | 使用者主動於網站報名或加入球迷會 | Email + 密碼註冊，經驗證信啟用 |
| **B. LINE 官方帳號 QR Code** | 現場招生、賽事、營隊、校園推廣、實體文宣 | 掃描 QR Code 加入官方帳號好友 → 依引導完成入會與綁定 |
| **C. Google 帳號** | 慣用 Google 生態系者、海外使用者 | 一鍵授權建立會員，免填密碼 |

> 三種管道建立的是**同一套會員資料**。同一人若先以 Email 註冊、之後再掃 QR 或用 Google 登入，皆以 Email 或手機號碼比對後**合併為單一帳號**，避免重複名單。

#### LINE 官方帳號入會流程

```
① 掃描 QR Code
   （現場立牌 / 文宣 / 官網頁面 / 報名完成頁 / Email 簽名檔）
        ↓
② 加入官方帳號好友
        ↓
③ 自動發送歡迎訊息
   「歡迎加入 TCRFC！點此完成會員註冊，即可查詢報名紀錄與賽程通知」
        ↓
④ 點擊連結開啟入會表單（於 LINE 內開啟）
   填寫：姓名、手機、Email、身分（球迷／學員家長）、有興趣的隊別
        ↓
⑤ 系統建立會員並綁定 LINE 帳號
        ↓
⑥ 完成：可於 LINE 圖文選單直接查詢，俱樂部亦可推播通知
```

**QR Code 佈署位置**：訓練場地與主場立牌、營隊與試訓現場、招生文宣與海報、官網 Footer 與聯絡頁、報名完成頁（引導加入以接收後續通知）、球迷會入會頁、賽事節目單。

**LINE 圖文選單（Rich Menu）建議項目**：`我的報名`、`近期賽程`、`課程報名`、`最新消息`、`聯絡我們`、`官方商店`。

> **設計原則**：LINE 管道的入會表單欄位**刻意精簡**（僅姓名、手機、Email、身分別），降低現場掃碼的放棄率；其餘資料待其實際報名課程時再補齊。

#### 與既有模組的整合

- **表單（10.1~10.7）**：登入狀態下自動帶入姓名／Email／電話，減少填寫欄位。
- **課程報名（P3）**：報名紀錄自動歸戶至會員，後台可由會員檢視其所有報名歷程。
- **球迷會（F2）**：球迷會員即為會員系統中具 `fan_club` 標記的會員，不另建名單。
- **Shopify**：官網會員與 Shopify 帳號**各自獨立**，不做單一登入（SSO）串接。**會員專屬優惠一律以發送 Shopify 折扣碼處理**，折扣碼可透過 LINE 推播或 Email 發送，後台可設定發送對象（層級／名單）與有效期限。
- **LINE 官方帳號**：作為入會管道與通知通路，不作為獨立的名單系統——所有 LINE 好友一旦完成入會即歸戶至會員資料庫（見 4.11 K5）。

- 未成年學員資料須由家長帳號代管，並取得監護人同意
- **LINE 綁定識別碼**（使用者於本官方帳號的專屬 ID）視同個資保護，不對外顯示、不匯出於一般名單
- 入會表單須載明個資使用目的與同意條款，與官網註冊採相同標準

### 4.12 L. 行事曆管理

#### L1 賽事行事曆總覽
- 以月曆呈現全部賽事（C4）與自建的俱樂部活動（L2），依隊別以色彩區分
- **隊別分軌檢視**：以 D1 / U15 / U14 / U12 為橫軸並排，一眼看出各隊當月賽程與衝突
- 支援拖曳調整日期 → **回寫至賽事資料**（改期時觸發通知）
- **衝突偵測**：同一場地或同一梯隊在同時段被重複安排時跳出警示
- 篩選：隊別、賽事類型、場地、狀態
- 檢視切換：月／列表

> 課程、營隊、專項訓練與學院日常課表**不進入行事曆模組**，於 P1／P2 課程模組獨立維護。

#### L2 自建事件（俱樂部活動）
- 用於非比賽性質的公開活動：記者會、簽名會、球迷見面會、公開訓練、休館公告等
- 欄位：標題（中／英）、所屬隊別（可複選，或選「俱樂部活動」）、起訖時間（支援全天與跨日）、地點（關聯 Venue）、說明、封面圖、外部連結或 CTA、是否公開於前台
- **重複規則**：每週／每兩週／每月，可設定結束日期與例外日期

#### L3 分類與顯示設定
- **隊別分類設定**：分類項目由 C1 球隊自動帶入（D1 / U15 / U14 / U12 …），此處維護前台顯示名稱（中／英）、排序、代表色、是否公開
- 賽事類型維護：聯賽／盃賽／友誼賽等名稱、識別色、排序
- 前台預設檢視（列表或月曆）、預設顯示範圍、預設選取隊別
- 各嵌入元件的預設篩選條件（首頁顯示哪些隊別、一線隊頁固定顯示 D1、各梯隊頁顯示該梯隊）
- **試訓是否同步至行事曆**：開關設定（預設關閉，試訓資訊維持於各招募頁面）

#### L4 訂閱與匯出
- **iCal 訂閱網址管理**：分別產生 `全站` 與 **各隊別（D1／U15／U14／U12）** 的 webcal 訂閱連結
- 匯出：指定期間的賽事匯出 CSV / .ics
- **批次匯入**：整季賽程以 CSV 匯入（與 C4 賽程匯入共用機制）
- 訂閱數統計（各隊別各有多少人訂閱）

#### 資料一致性原則
- 行事曆是**彙整層而非資料源**：賽事仍於 C4 賽事模組維護，行事曆僅提供統一檢視與編輯入口
- 僅 L2 自建事件為行事曆專屬資料
- 賽事時間或狀態異動時，若已有會員標記參加或訂閱，自動觸發通知（見 K4）
