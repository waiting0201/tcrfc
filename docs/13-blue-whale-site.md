## 1. 一分鐘理解

台中藍鯨女足的官方網站：**獨立網域、獨立前台專案、中英雙語**，取代現有的 Google Sites 站台（[www.tcbw2014.com](https://www.tcbw2014.com/)，10 個單元、無多語系、無功能模組）。

**與主站共用同一套後台與資料庫，但資料流分開**（以 `club_id` 區隔）。

| 層面 | 主體 | 對系統的意義 |

| **內容與品牌** | **台中藍鯨** | 標誌、品牌色、文案署名、社群連結一律為藍鯨 |

## 4. 踩雷點

0. **總則優先於一切「這裡要不要不一樣」的疑問。** 藍鯨站與主站是同一套網站，**只有配色不同**；除了第 3 節那四項單元取捨，任何版型、區塊、流程與功能的差異一律**不成立**。要做出差異＝規格變更，須先改規劃書。
1. **這份規劃書只寫差異。** 看到藍鯨規劃書沒寫某個功能細節，**不是漏寫**，是因為它與主站相同——去讀主站規劃書的同名章節。兩者衝突時**一律以主站規劃書為準**。
2. **`BW1` 不是第二個 `D1`。** `Team.code` 全站唯一，**不得改成「俱樂部 × 代號」複合鍵**——它是行事曆訂閱網址與 `/schedule/d1/` 的識別鍵，已在外流通。
3. **藍鯨站有自己的會員與商店，但收款主體仍是俱樂部**（代收代付）。單一 LINE Pay 商店號、單一發票抬頭。**藍鯨不申請自己的商店號、不使用自己的發票字軌。**
4. **購物車不得跨俱樂部混買。** 切換站台即切換購物車。四個理由見主站規劃書 4.13——**運費規則在混買下定義不出來**是最硬的一條（現行只有單一固定運費＋免運門檻，級距引擎明文不做）。
5. **兩隊贊助商必須分區，不得混列。** 合約各自簽的；同一家公司同時贊助兩隊時是**兩筆 `Sponsor`**。
6. **兩隊球季不同步**（木蘭聯賽 vs 企甲）。到期日、續會提醒各自計算；`Season.code` 的唯一鍵是 `(club_id, code)`。
7. **藍鯨會籍有自己的一張卡。** 「一張卡一組 token」與「驗證頁不得加適用球隊欄位」兩條**維持不變**——前者約束的是卡與 token 的 1:1，不是人與卡的 1:1。
8. **標誌必須是向量主檔。** **不得自行造標、不得從網頁截圖描摹、不得自行排字、不得把點陣圖放大充當向量。** 找不到就回頭找原始檔或重製（第二代 LOGO 自 2016 年沿用至今，原始檔應該存在）。未到位前對應區塊**不顯示**，不得放假圖或空 Logo 格。
   💡 **藍鯨由磐石在 running，這些資產在自己手上**——是盤點問題不是外部依賴（背景見 [`15-out-of-scope-record.md`](15-out-of-scope-record.md)）。
9. **球員照片須有肖像同意**，未成年須監護人同意。同意未到位的球員不顯示照片。
10. **「合作球隊管理」角色第一階段可先不指派使用者**——藍鯨由磐石的團隊在維護，用自己既有的帳號即可。
    **但資料範圍權限仍要做**：`club_id` 已鋪到 50 張表，後台每個清單查詢都要決定要不要過濾，這是**系統地基**，補在後面等於重寫查詢層。**角色定義先建好、先不指派即可，不擋上線。**
11. **獨立網域帶來 Universal Link 的新條件。** App 深連結要能回退到藍鯨站，該網域**必須由可控方持有**並能放 `.well-known/apple-app-site-association` 與 `assetlinks.json`。控制權不在手上則藍鯨深連結不得上線。
12. **GEO 的檔案兩站各一份，不共用。** 藍鯨站有自己的 `llms.txt`（繁中英文各一份）與 `robots.txt`（規劃書 §7 第 4 點、主站 `GEO-01`／`GEO-02`／`GEO-09`）。
    共同內容（`club_id` 為空）的**事實敘述以 canonical 所在站為準**，本站連結導向、**不重複陳述**。
    ⚠️ **`GEO-02` 排除 U15／U12 球員照片路徑**——這是個資防線不是 SEO 設定，不得為了讓 AI 多抓而放寬。
13. **品牌色不能沿用磐石的明暗階。** 藍鯨主色是藍色系，明度分布與磐石桃紅不同，**AA 安全版與實心按鈕 hover 版須重新計算並驗證 4.5:1**。
14. 🔴 **木蘭聯賽 25/26 起球季改為「8 月 → 次年 6 月」**（與 FIFA、亞冠、轉會窗口接軌，來源：舊站 `/木蘭聯賽` 的賽制變革說明，見 [`../content/blue-whale/competitions.md`](../content/blue-whale/competitions.md)）。
    這把上面第 6 點的「兩隊球季不同步」從一句原則變成具體約束：**`Season` 的起訖不是曆年**，
    所以**會籍到期日與續會提醒的算法必須照這個定義**，不能假設球季＝1 月到 12 月。
    ⚠️ 舊站的會員規則第七條寫「會籍期限＝自繳費日起最近一個賽季」——那份章程本身不能用（見 `STATUS.md` C-8），
    但「一個賽季」這個期限概念要不要沿用、跨年球季怎麼算到期日，**是規格問題不是實作問題，必須先確認**。
15. ⚠️ **「臺中唯一」這類敘述要重新檢查。** **2025 年成立的「台中櫻花」是臺中市第二支社會女足隊**，
    與藍鯨同城、同在木蘭聯賽（25/26 八隊名單裡兩隊都在）。舊站有多處「台中足球之都」「唯一」語氣的敘述，
    **沿用前要逐句確認現在是否仍然成立**——這種敘述一旦寫進 Schema 與 `llms.txt` 就會被 AI 引用擴散。
16. ⚠️ **舊站同一份事實有兩份且不一致，不得原樣搬遷。** 賽季紀錄同時出現在 `/關於台中藍鯨` 與 `/一線隊` 且內容有出入；
    2023 賽季一線隊頁寫「10 勝 4 平 1 敗」，但該季 15 場戰績表是 **6 勝 6 平 3 敗**；球員「李琇琴／李綉琴」兩種寫法並存。
    **新站不得沿用任何未經核對的統計數字**——這正是 `GEO-06` 事實單一來源要解決的問題。
17. 🔴 **英文正式全名在舊站就有三種寫法並存**：`Taichung Bluewhale`／`Taichung Blue Whale Women's Football Team`／`Taichung blue whale`，
    **隊徽兩代的使用年份在舊站也互相重疊（2016–2023）**。這不是「客戶還沒給」，是**舊站自己就不一致**。
    ⛔ **開發端不得自行挑一個**（`ClubIdentity.brandTagEn` 對藍鯨一律 `null`，見 §6 紀律 11）——
    選錯會一路汙染 Schema、`llms.txt` 與 App，必須由客戶指定唯一寫法（`STATUS.md` B-5）。

## 6. 前台建置的技術判斷

### ✅ 主站與藍鯨共用一個 Nuxt 映像檔（2026-09-20 定案）

**一個映像檔、兩個容器、靠 `NUXT_PUBLIC_CLUB` 環境變數切品牌。** 已由 `frontend-architect` 驗證可行，
前提是現有 `site/src/assets/css/tcrfc.css` **全部用 CSS custom properties、沒有 Tailwind 也沒有 CSS-in-JS**
（已實查：`:root` 外只有 4 個硬編碼色碼，是 LINE 的品牌綠，本來就不該是俱樂部變數）。

**色彩切換用 `[data-club]` 屬性選擇器**，兩組色票都編譯進同一份 CSS：

```css
:root, :root[data-club="tcrfc"]{ --brand:#E0218A; --brand-aa:#D61E83; … }
:root[data-club="bw"]        { --brand:#2196D5; --brand-aa:#1A78AA; … }
```

`app.vue` 用 `useHead({ htmlAttrs: { 'data-club': useRuntimeConfig().public.club } })`——
**SSR 階段就決定、隨 HTML 一起吐出**，沒有 hydration mismatch 風險，也不需要動態組 `<style>` 字串。

### 🔴 六條開發紀律（破了其中一條，共用就悄悄失效）

| # | 紀律 | 不遵守會怎樣 |
|---|---|---|
| 1 | **色彩永遠只能是 CSS custom properties**，⛔ 不得引入任何把顏色編譯成字面值的工具（Tailwind JIT class、CSS-in-JS 靜態抽取） | 編譯後的 CSS 裡是 `#E0218A` 而不是 `var(--brand)`，**runtime 換色直接失效** |
| 2 | **club 專屬靜態資產（favicon、OG 圖、apple-touch-icon）兩份都打包進同一映像檔**，`useHead` 依 runtime 變數選路徑 | 寫死 `/favicon.ico` 的話藍鯨站會顯示磐石的圖示 |
| 3 | 🔴 **單元開關只能有一個真實來源**：寫一個 `isUnitEnabledForClub(unitCode, club)`，**route middleware、導覽選單、sitemap、`llms.txt`／`robots.txt` 四處都呼叫它** | 四處各寫一份判斷，新增頁面時漏掉一處 → 「頁面 404 了但還留在選單裡」或「選單拿掉了但 sitemap 還在遞交」 |
| 4 | **選定 SEO 模組的第一件事就是實測 `NUXT_PUBLIC_SITE_URL` 能不能 runtime 覆寫** | ⚠️ **這是唯一「技術上真的可能做不到」的環節**，見下方 |

### ✅ `apps/web/` 骨架的執行層決定（2026-09-21，S0-9a，`frontend-architect`）

以下是 `apps/web/` 實際建立骨架時定案的做法，補在上面的 spike 結論之後：

- **選擇明確關閉 `nuxt-og-image`**（`nuxt.config.ts` 設 `ogImage: false`），沒有裝
  `@takumi-rs/core`。理由：mockup 的 OG 圖是固定靜態檔（`shell.html` 的 `og:image`），
  沒有「依文章標題動態產生 OG 卡片」這類需求；`@takumi-rs/core` 是原生二進位相依，
  在 `node:22.12-alpine` 上會增加建置複雜度與映像檔體積，沒有對應功能需求就不引入。
  之後真的要做動態 OG 圖，再回頭裝這個相依、打開這個子模組。
- **藍鯨色票覆寫檔獨立成 `public/assets/css/club-bw.css`**，用
  `:root[data-club='bw']{...}` 七個變數覆寫，**不改 `tcrfc.css` 本體**，載入順序固定在
  `tcrfc.css` 之後（`app/app.vue` 的 `useHead` 兩個 `<link>` 依序排列）。兩站共用同一份
  `<link>` 清單也安全——`tcrfc` 站台下這個檔案沒有任何選擇器會命中。
- **`tcrfc.css` 整份放進 `public/`，不透過 Nuxt／Vite 的 `css:` 設定選項載入**，
  一律用純靜態資源的 `<link rel="stylesheet">` 引入。原因：走 Vite 的 css pipeline
  有被處理（例如被 PostCSS 轉寫、加雜湊檔名）的風險，跟「一個位元都不准改」互相矛盾；
  純靜態資源複製不會被建置流程碰到。已用 SHA-256 比對確認 `public/assets/css/tcrfc.css`
  與 `site/src/assets/css/tcrfc.css` 逐位元組相同。
- **`<html lang>` 改放 `nuxt.config.ts` 的 `app.head.htmlAttrs.lang`，不放元件層 `useHead`**：
  `@nuxtjs/seo` 的 `nuxt-seo-utils` 子模組會自己對 `htmlAttrs.lang` 設一次值（預設回退
  `en`），實測它跟元件層 `useHead` 的合併是「後註冊的呼叫覆蓋同一個 key」，不受
  `tagPriority` 影響；只有 `nuxt.config.ts` 的 `app.head` 才穩定生效。詳見
  [`docs/18-work-errors.md`](18-work-errors.md) E-17。全站固定不隨 club 變動的屬性
  （`lang`）放這裡，只有隨 club 變動的屬性（`data-club`）留在 `app.vue` 的動態 `useHead`。

  排除（本站上線前必然全站 noindex，見 `CLAUDE.md` 第 5 條）。改法：`sitemap.enabled: false`

**下方的七個色彩變數與換膚原則一字未改**，改變的只是它們套用在哪一種專案結構上。

<summary>原靜態骨架時期的做法（保留供重寫時參考）</summary>

**新增 `site-bw/`，與 `site/` 平行，複製骨架不共用建置。**

`site/build.mjs` 只有 116 行、零相依、**不認識 TCRFC**——它只認 `src/partials/shell|header|footer` 三個檔名與 `{{token}}` 語法，複製後**一行都不用改**。共用建置反而要引入設定檔與條件分支。

**換膚只改 7 個變數，值已定案**（規劃書 §8.1，取自隊徽）：`tcrfc.css` 全站色彩只從 `:root` 流出，CSS 本體僅 3 處硬編碼色碼（全在 `:root` 定義與 Pantone 註解）。

```css
--brand:#2196D5;        /* 隊徽藍。對白 3.29:1，只能用於大字與色塊 */
--brand-aa:#1A78AA;     /* 對白 4.87:1 — 白底小字一律用這個 */
--brand-bright:#50B0E4; /* 深底 hover */
--brand-deep:#156088;   /* 實心按鈕 hover，白字 6.86:1 */
--ink:#040000;          /* 隊徽黑 */
--ink-2:#1D1919;
--ink-trim:#040000;
```

`shell.html` 的 `theme-color` 改為 `#2196D5`。完整說明與對比度驗證見 [`06-conventions.md`](06-conventions.md) §2。

**紀律由 `verify.mjs` 維持**：它會 grep 阻擋硬編碼品牌色，複製到 `site-bw/` 後把清單換成藍鯨色碼即可自動守住同一條線。

⚠️ **65/80 頁帶自己的 inline `<style>`**，複製會連帶帶過去，須靠 verify 掃出漏網色碼。
