> 執行層文件。對應收件結構 [`../TCRFC_資料收件夾/`](../TCRFC_資料收件夾/)。

## 1. 設計前提

客戶手上已有大量既有檔案（簡報、招生 DM、粉專貼文、比賽照片），**不要求他們重新產出內容**。
收件的設計原則：

1. **資料夾結構＝表格**。分類、日期、對象由**路徑**承載，客戶只需拖放檔案。
2. **一定要有垃圾桶**。`99_未分類` 讓客戶永遠不會因為「不知道放哪」而停住。
3. **空資料夾＝缺件清單**。隨時掃一次就知道進度，不必反覆發信詢問。
4. **★ 標記＝第一批**。對應 Phase 1（見 [`08-roadmap-decisions.md`](08-roadmap-decisions.md)），不要等全部到齊才開工。

### 2.2 資料來源衝突時以收件夾為準

**同一件事在不同來源說法不一時，一律以 [`藍鯨_資料收件夾/`](../藍鯨_資料收件夾/) 裡的檔案為準**（使用者 2026-10-07 定案）。
從舊站 `www.tcbw2014.com` 頁面或官方 Google 行事曆抓回的 [`content/blue-whale/`](../content/blue-whale/README.md) 只是遷移底稿，順位在收件夾之後。

| 情況 | 做法 |
|---|---|
| 收件夾有、抓取資料也有，兩者不同 | **採收件夾**。抓取資料原文不改，在該處加 `> ⚠️` 註記「以收件夾為準」並寫出收件夾的檔案路徑 |
| 只有抓取資料 | 暫用抓取資料，衝突照原樣並列、不擇一，等收件夾補件 |
| 收件夾同一資料夾內有新舊版本 | 照說明檔「新舊版本」：資料夾本層為最新，`舊版` 子資料夾不採用 |

🔴 **抓回來的檔案不得放進收件夾**——放進去就會被當成客戶原稿而取得優先權，而且收件夾會經 Drive 同步出去。
抓取原檔放 `content/<站>/_raw/`（不納版控，見 `.gitignore`）。

**Drive 上的位置（兩份相同做法）**：兩份收件夾都是用 Drive for Desktop（開發端的 Workspace 帳號）的**「我的 Mac」資料夾同步**，
直接從專案裡的本機路徑同步上去，所以在 Drive 網頁上要到左側「**電腦**」區塊找，**不在「我的雲端硬碟」裡**。
好處是有人在 Drive 上放檔案，專案資料夾就會直接收到，盤點時不用另外下載。
⚠️ **Drive for Desktop 沒在執行時，兩邊都不會同步**（2026-10-05 就發生過程式在背景關閉、上傳無聲失敗的情況）。看到收件夾沒更新，先檢查選單列有沒有 Drive 圖示。

> ⚠️ **打包不要用 macOS 內建的 `zip`**——它不會設 UTF-8 旗標（general purpose bit 11），Windows 解壓中文檔名會亂碼。
> 改用 Python `zipfile`（非 ASCII 檔名自動設旗標），並先把路徑正規化成 NFC。打包後用
> `python3 -c "import zipfile;print(all(i.flag_bits&0x800 for i in zipfile.ZipFile('X.zip').infolist()))"` 確認為 `True`。

## 3. 四個階段

### 階段一：盤點
掃描收件夾，產出清單：每個頁面有沒有料、每個檔案是什麼、圖片解析度是否足夠。
這份清單同時就是**給客戶的缺件通知**。

輸出建議欄位：`路徑｜對應頁面｜檔案類型｜大小／解析度｜狀態（可用／需補／需轉檔）`

### 階段二：抽取
| 格式 | 處理 |
|---|---|
| `.docx` / `.pdf` / `.pptx` / `.xlsx` | 抽文字與表格 |
| `.jpg` / `.png` | 直接可用；讀路徑判斷歸屬 |
| `.heic` | **需先批次轉檔**（iPhone 拍攝常見） |
| 影片 | **無法讀內容**，僅登記為素材，剪輯另行處理 |

### 階段三：改寫（最花時間，也是價值所在）
客戶素材多為簡報稿、DM、粉專貼文，語氣與長度都不是網頁用的。依 [`02-frontend-spec.md`](02-frontend-spec.md) 各頁版型改寫為：
`頁面主標題｜導言｜內文區塊｜CTA｜SEO 描述`，長度依 [`06-conventions.md`](06-conventions.md) §5。

同時填入 `zh` 欄位、保留 `en` 欄位空位（見 [`05-i18n-seo.md`](05-i18n-seo.md)）。

> **這一步必須逐頁給客戶確認再套用。** 品牌用語、球員姓名的官方寫法、獎項全名，猜錯的成本高於多問一次。

### 階段四：套版
轉為網站可用的內容格式，接上頁面。**格式取決於技術選型——目前未定案**（見 [`08-roadmap-decisions.md`](08-roadmap-decisions.md) 待確認 §1）。
在選型定案前，改寫產物先以 Markdown + front matter 保存，不綁定特定 CMS。

## 4. 素材品質標準

先講清楚，事後補拍的成本遠高於一開始要求：

| 用途 | 要求 |
|---|---|
| Hero 主視覺 | 長邊 ≥ 2400px，橫向構圖 |
| 球員照／人物照 | 長邊 ≥ 1200px |
| Logo | PNG 透明底或 SVG／AI；**夥伴 Logo 需深淺底兩版**（後台 E1 要求） |
| 可下載文件 | PDF（章程、年報、提案簡介） |
| 圖片格式 | 上站一律轉 WebP（後台 B3 自動處理） |

**不接受**：從 Word／PPT／LINE 裡取出的二次壓縮圖；螢幕截圖充當主視覺。

## 5. 個資與肖像權

收件夾內容含未成年學員照片與可能的個資，處理時：

- **不要外傳、不要放進會被公開或索引的位置**
- 球員照、學員照、夥伴 Logo 的使用授權須於上線前逐項確認
- 未成年學員資料須有監護人同意（規劃書 §8 個資要求）
- 需要公開展示的素材，先確認是否已取得同意
