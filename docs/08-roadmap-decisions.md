## 1. 開發階段

> 🔴 **v3.0 排程前提——多俱樂部是地基，不是後期擴充**
> `club_id` 一旦鋪到 50 張表，後台**每一個清單查詢都要決定要不要過濾**。先當單一俱樂部開發、日後再補，等於**重寫整個後台查詢層**。
> 因此 **`Club` 型別、`club_id` 維度與 `AdminUserClub` 資料範圍權限一律排入 Phase 1**，即使藍鯨官網本身晚一點才上線。
> 同理，**`Membership` 必須與會員系統同時做**（Phase 2）——會籍從 `Member` 拆出來是結構變更不是加欄位。

### Phase 1 — 品牌基礎與轉換（MVP，約 8–10 週）
- **多俱樂部地基（v3.0，最優先）**：`Club`／`Competition` 型別、50 張表的 `club_id` 維度、後台**站台切換器**、`AdminUserClub`／`AdminUserTeam` 與**資料存取層強制**、`J4 俱樂部與授權管理`
- 首頁、02 關於台中磐石、03.1 一線隊（基本）、04 學院（4.1／4.2／4.7）、05 課程（5.1／5.2）
- **06 女子足球介紹頁**（單頁，成本低可一併完成）
- 07 新聞中心（全分類）、10 表單中心（7 類）、Location & Map
- **12 FAQ 獨立單元**（先建 3–4 個高頻主題）
- **13 賽事行事曆**：以 `D1／U15／U14／U12` 為主分類，賽程／賽果切換、列表與月曆檢視、單場 .ics
- 後台：內容管理、新聞、球隊／球員／教練、課程與報名、FAQ、行事曆總覽與自建事件、詢問收件匣、SEO 基礎、權限。**圖片一律欄位直傳**（規劃書 §4.0 上傳通則）
- **多語系框架建置**（繁中先上線，`en` 欄位與 URL 結構同步就位）

### Phase 2 — 商業、會員與深度內容（約 6–8 週）
- 09 合作夥伴與贊助全區（含提案下載與 Lead 追蹤）
- 03.2~03.5 球員發展、國際通道、球員故事
- **11 慈善與社會影響全區**
- 05.3~05.5 冬令營、專項訓練、校園社區
- **會員系統（K 模組）**：Email 註冊、LINE 一鍵登入與綁定、兩層級會籍、**電子會員卡與公開驗證頁**、**權益對照表**（含抽獎資格條目）、**特約店家清單（8.4）**、升級與續會、球衣登記
- **行事曆進階**：各隊別 webcal 訂閱、後台分軌檢視／衝突偵測／拖曳改期
- 後台：商業模組、慈善模組、試訓管理、報名進階、**會員管理 K1–K4（名單／會籍與方案／球衣發放／特約店家與權益）**、行事曆進階
- **英文版內容上線**

### Phase 3 — 文化與社群（約 6 週）
- 08 台中磐石文化：漫畫閱讀器、球迷會 8.2（付費會籍介紹與加入頁，整合會員系統）
- **站內官方商店（8.3 + 後台 S 模組，v2.6 新增）**：商品與規格、庫存、購物車、結帳、**LINE Pay 串接**、**電子發票開立**、出貨與物流、訂單查詢、退貨退款、商店報表。**規模比照舊 Wix 商店**（不含會員價、折扣碼、多元付款、運費級距），工時較完整電商大幅收斂。**依賴會員系統（Phase 2）已上線**；**俱樂部 LINE Pay 商店號與發票服務的申請須提前於 Phase 2 啟動**，否則卡住本階段
- **舊商店退場**：站內商店上線後停售舊官網 Wix 商店，商品與分類網址 301 轉址（H 模組批次匯入）
- **會員管理 K5 抽獎名單管理**：名單快照與序號配發、兩種 CSV 匯出、中獎人回填、獎品發放、公布稿交接 B2。（抽獎資格本身屬 K4 權益條目，隨 Phase 2 一併上線）
- 賽事積分榜、球員數據自動彙總
- 電子報整合

### Phase 4 — 優化與擴充（持續）
- FAQ 成效優化、搜尋無結果關鍵字回饋
- 數據儀表板深化、A/B 測試、個人化推薦
- 選配評估：票務、會員點數、**特約店家掃碼核銷與成效報表**、**物流商 API 串接**、**會籍改走商店結帳**（v3.0 起優先度提高）、**藍鯨獨立收款**（須先確認會計與法人前提）、**購物車跨俱樂部混買**（須改為主單＋子單結構）
- **已取消**：`Shopify Storefront API 商品同步` 隨 v2.6 外部商店退場而取消

> **v2.6 起電商與金流已納入 Phase 3**（原「購物全數由 Shopify 承接」的前提已作廢），這是 Phase 3 **工時增幅最大的一項**，且引入本站第一條對外收款金流。會員系統範圍於 v2.0 收斂為「會籍 × 特約折扣 × 球衣」，工時較 v1.9 下修；v2.3 加回**抽獎資格**，但系統只做名單與匯出、不做隨機抽出，工時增幅有限。

## 3. 待確認事項（40 項）

**擋開發的（優先問）**

1. **舊 Wix 商店的退場與轉址** — v2.6 已定案自建站內商店，**Shopify 不再是導流目標**（原待確認項關閉）。改為待確認：舊 Wix 商店何時停售？上線前的訂單與庫存怎麼交接？5 個商品與分類網址的 301 對應表誰確認？
2. **既有官網內容遷移範圍** — www.tcrfc.tw 哪些保留／改寫／捨棄（新聞類建議留近 1–2 年）
3. **特約店家首波名單** — 本站不做票務，付費會籍的價值全靠**店家折扣與球衣**，首波名單的數量與品質**直接決定付費層能否成立**，須於上線前談定
4. **年費金額與方案設計** — 單人方案費用？是否設家庭方案（1 成人 + N 小童）？各含幾件球衣？

**影響規格細節**

5. **球季起訖日與季中入會計價** — 會籍以球季計期，需確認球季起訖，以及季中入會是否按比例折價
6. **會費的 LINE Pay 收款形式** — **會籍會費**採收款連結／官方帳號帳單（本站預設，不碰金流），或比照慈善站改走 LINE Pay API？慈善站**已定案正式串接**，商家帳號完成後會費要不要沿用可另評估
7. **會員編號格式** — 建議 `TCR-<球季>-<流水號>`
8. **球衣尺碼表與備貨量** — 提供的尺碼範圍（成人／童裝）與依尺寸的備貨策略
9. **捐款收據與勸募資格** — 已於慈善捐款平台規劃書 §5 規範（電子發票與捐贈收據兩種，依項目設定）。**勸募資格屬該平台的上線前提**，須由俱樂部與會計師／法務確認
10. **英文版內容產出方式** — 俱樂部提供／委外翻譯／先上重點頁面？**影響 Phase 2 時程**
11. **慈善金額是否公開** — 預設不公開，是否有需公開的個案？
12. **試訓是否顯示於行事曆** — 預設關閉，可於後台開啟
13. **賽事購票與轉播資訊** — 是否有售票管道或轉播平台需顯示於賽事卡片
14. **漫畫更新頻率** — 影響「最新集數」與首頁曝光規劃
15. **個資保存期限** — 規劃書要求七類表單顯示保存期限說明，但未定實際年限。**法遵項目，擋表單上線**，須由俱樂部與法務確認
16. **抽獎獎品的價值上限與扣繳門檻** — 單一獎項是否刻意壓在扣繳門檻以下（即可**免蒐集中獎人身分證字號**）？門檻金額、扣繳率、免扣繳仍須列單申報的義務、非境內居住者規定，**須會計師確認**後寫入活動辦法
17. **開獎頻率與場合** — 每季／每球季／搭配特定主場賽事日？是否直播並留存錄影作為開獎存證
18. **領獎期限與逾期未領處理** — 期限幾日？逾期後由備取遞補、重抽、作廢，或轉作下次獎品？須於活動辦法明訂
