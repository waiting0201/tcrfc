## 1. 多語系

| 項目 | 規則 |
|---|---|
| 語系 | **繁體中文（預設）／英文**；日文列為後續評估，**不實作但架構須預留** |
| URL | `/zh/…`、`/en/…` 獨立網址 |
| hreflang | `zh-Hant`、`en`、**加上 `x-default`** |
| Fallback | 未翻譯內容顯示繁中，並標示「本頁尚無此語系版本」（fallback 或隱藏可於後台設定） |
| 切換行為 | 停留於當前頁的對應語系版本，不要跳回首頁 |
| 擴充 | 新增語系不需改程式 |

**英文版優先範圍**（Phase 2 上線時的順序）：
首頁 → 02 關於台中磐石 → 03.4 國際發展通道 → 04 學院 → 09 合作與贊助 → 10 聯絡表單 → 12 FAQ → 13 賽事行事曆

**後台支援**（I 模組）：翻譯狀態總覽矩陣（可篩「缺英文」）、字串翻譯表（按鈕／表單標籤／提示／錯誤訊息）、日期與數字格式、字型設定。
**權限**：翻譯人員角色只能編輯 `en` 欄位，不能改繁中原文與發布狀態。

## 2. SEO 九項基礎

| 基礎 | 實作方式 |
|---|---|
| 清晰的架構與層級 | URL 直接對應網站層級，如 `/zh/academy/join/` |
| 關鍵字導向內容 | 每頁可設主要關鍵字，提供標題／H1／首段的使用檢查 |
| 結構化資料 | Organization、SportsTeam、SportsEvent、Event、Person、Article、Course、FAQPage、BreadcrumbList，**以及 Product 與 Offer**（v2.6：商店已在站內，商品頁由本站輸出 Product Schema，含價格、幣別與供貨狀態） |
| 內部連結 | 文章關聯球員／球隊／課程並自動產生互連區塊；**孤立頁面偵測** |
| 行動友善 | Mobile First、觸控目標 ≥ 44px、行動版 CTA Bar |
| 載入速度 | 圖片**一律取用後台 §4.0 通則產生的衍生檔**（WebP、依版位挑 1280／640／320、**不得直接引用主檔**、必帶寬高、首屏外 lazy load）、CDN、關鍵 CSS 內聯；**LCP < 2.5s、CLS < 0.1、INP < 200ms** |
| 高品質原創內容 | 球員故事、比賽報導、漫畫、**慈善事蹟**為差異化資產 |
| 定期更新 | 排程發布 + 內容行事曆檢視 |
| 多語系 | 見上節 |

## 3. GEO（生成式引擎最佳化）　`主站規劃書 §7`

> 🔵 **v3.6 起 GEO 是正式規格，不是建議。** 九項與 SEO 九項基礎同等級、逐項可驗收，**兩個官網各自完整實作一份**。

| 代號 | 一句話 | 最容易做錯的地方 |
|---|---|---|
| `GEO-01` | **`llms.txt`**：站點定位、代表頁、事實摘要、授權與引用方式、聯絡窗口 | **繁中英文各一份、兩站各自一份**；由後台 `H` 維護並隨發布重產，**不以人工改檔** |
| `GEO-02` | **AI 爬蟲授權**：`robots.txt` 明列允許的 AI 使用者代理 | **全站允許，但排除**會員中心、七類表單、訂單查詢、`/m/<token>` 會員卡驗證頁、**未成年與學員照片路徑** |
| `GEO-03` | **事實單一來源**：重要事實全站只有一個維護處 | 同一事實**不得在兩處各寫一份**——AI 抓到互相矛盾的版本會拖垮整站可信度 |
| `GEO-04` | **事實雙重呈現**：結構化資料 ＋ 明確文字 | **不得只存在於圖片、影片或 PDF 之內** |
| `GEO-05` | **Schema 完整輸出** | **必填欄位不得留空**；資料不足時**不輸出該型別**，不輸出殘缺 Schema |
| `GEO-06` | **FAQ 是核心資產**：單元 12 與 G-12 一律輸出 FAQPage | 問題寫成**完整句子**（不用關鍵字片語），**答案首句即結論** |
| `GEO-07` | **可擷取的內容結構** | H1 唯一、H2/H3 不跳階、首段是**獨立成立的摘要段**、**不以圖片排版承載文字** |
| `GEO-08` | **引用資訊**：canonical、發布與更新時間、語言、作者 | 更新時間要真的更新，不是發布時間複製一份 |
| `GEO-09` | **兩站各自獨立** | 共同內容（`club_id` 為空）的事實敘述**以 canonical 所在站為準**，另一站連結導向、**不重複陳述** |

**GEO 不做的事**：✗ 站內 AI 問答機器人　✗ AI 內容生成或自動改寫　✗ 為 AI 另建 API 或 MCP 端點　✗ `llms-full.txt` 全文匯出　✗ 任何搜尋或引用排名的驗收標準

**後台承接**：`H` 模組新增三項——`llms.txt` 維護、AI 爬蟲授權（含排除路徑）、結構化資料完整性檢查。
**不新增資料型別**：設定值存於 `Setting`，事實沿用既有欄位（`Setting`／`Club`／`Team`／`Venue`／`ImpactMetric`）。

⚠️ **`GEO-02` 的排除路徑是個資防線，不是 SEO 設定。** 不得為了「讓 AI 多抓一點」而放寬；
肖像同意未到位的素材本來就不得公開（見 [`14-invariants.md`](14-invariants.md)）。
⚠️ **慈善捐款平台不適用本節**——該平台明文不做 SEO／GEO（其規劃書 §3），頁面維持可被索引即可。

**藍鯨站特有**（藍鯨規劃書 §7 第 4 點）：自己的 `llms.txt` 與 `robots.txt`，
自己的事實清單（成立 2014-04-12、AFC 執照、木蘭聯賽、太原足球場與豐原體育場、吉祥物布魯威）；
`GEO-02` 排除 **U15／U12 球員照片路徑**。

## 4. 非功能性需求

| 面向 | 需求 |
|---|---|
| 效能 | 首頁 LCP < 2.5s（4G）、Lighthouse Performance ≥ 85 |
| 相容性 | Chrome / Safari / Edge / Firefox 最新兩版；iOS 15+、Android 10+ |
| 無障礙 | **WCAG 2.1 AA** |
| 安全 | HTTPS 強制、後台 2FA、CSRF／XSS／SQL Injection 防護、上傳類型與大小限制、後台 IP 白名單（選配）；會員系統另需密碼雜湊、Session 逾時、登入失敗鎖定、防暴力破解；**商店（v2.6）**：付款於 **LINE Pay** 端完成、**不存卡號**、回呼**驗簽且冪等**、訂單查詢 token 不可推導且具時效、退款與匯出雙重授權 |
| 個資 | 報名／詢問／會員資料（含 LINE 綁定識別碼）**與訂單收件資料**加密儲存、保存期限政策、當事人刪除請求流程；**未成年學員資料須取得監護人同意**。**交易紀錄與發票依稅法保存，優先於刪除請求**：帳號刪除時訂單只留法定必要欄位 |
| 可用性 | 99.5% 上線率；每日備份、異地保存 30 天 |
| 擴充性 | 新增年齡層／賽季／課程類型／語系**不需改程式**；女足日後升級可直接沿用球隊模組；**商店的金流商、發票商與物流方式須可抽換**，不得寫死於訂單流程 |
| 監控 | 錯誤追蹤（Sentry 類）、Uptime 監控、**表單送出失敗告警**；**商店另需付款失敗率、金流回呼失敗與庫存負值告警** |

## 4b. 多俱樂部下的 SEO（v3.0 新增）

本系統承載兩個官網：主站（`tcrfc.tw`）與**台中藍鯨官網**（獨立網域，見 [`13-blue-whale-site.md`](13-blue-whale-site.md)）。兩站共用後台與資料庫，SEO 上有三件事要處理：

**① 共同內容的 canonical 歸屬**
`club_id` 為空的文章（＝兩隊共同）**會在兩站都出現**。若兩站各發一份 canonical，等於**重複內容**，兩邊都會被稀釋。
> **建議：canonical 掛主站，藍鯨站以連結導向。** 這也是 `Article.slug` **維持全站唯一**（不改成 `(club_id, slug)`）的原因——共同文章必須有**單一**網址，App 的系統分享也只能送出一條連結。
> ⚠️ **待客戶確認**（規劃書第 10 章第 38 點）。

**② 兩站各自的 `hreflang` 群組**
兩站都做繁中＋英文，**但 `hreflang` 是站內的語系對應，不跨站**。主站的 `/zh/about/` 對應主站的 `/en/about/`，不對應藍鯨站的任何頁面。**不要把兩站的頁面互設為 hreflang 替代版本**——它們是不同的內容主體，不是同一頁的不同語言。

**③ 藍鯨舊站的 301 轉址**
既有 Google Sites 的 10 個單元須逐一對應至新站。**其網址含中文路徑**，轉址表必須人工整理，無法自動推導。

> **兩站的 `noindex` 各自獨立控制。** 藍鯨站上線前同樣要維持 `noindex`，且**其素材若含未成年球員照片，肖像同意未到位前不得移除**——比照主站規則。

## 5. 舊站遷移

- 既有官網 www.tcrfc.tw 上線時**全站 301 轉址**至新站對應頁，保留 SEO 權重（後台 H 模組支援批次匯入對照表）
- 內容遷移原則：先盤點分類（保留／改寫／捨棄），**只遷移仍具時效與品質的內容**
- 新聞類建議保留近 **1–2 年**；過舊內容不逐篇搬移，但**網址仍要轉址**
- **舊 Wix 商店的 5 個網址**（`/product-page/…`、`/category/…`）於站內商店上線後 301 轉址至站內對應商品頁（v2.6）
