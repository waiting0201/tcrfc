# 10 — 慈善捐款平台

> 來源：[`../output/TCRFC_慈善捐款平台功能規劃書.md`](../output/TCRFC_慈善捐款平台功能規劃書.md)（v1.0，共 672 行）

獨立網域的掃碼捐款平台，**共用官網後台與資料庫**。主站單元 11 只做介紹與導流，捐款金流全在這裡。

---

## 1. 一分鐘理解

```
店家貼 QR → 客人掃碼 → 落地頁（顯示店家名稱） → 選捐款項目
          → 項目詳情頁（最下方是捐款表單） → LINE Pay → 發票／收據 → 感謝信
```

| 前提 | 值 |
|---|---|
| 網域 | **獨立網域**（名稱待定，最優先確認——QR 印了就難改） |
| 前台 | **完全獨立的專案**，不共用主站 `site/` 的 73 頁骨架 |
| 後台／資料庫 | **共用官網**，新增 `N. 慈善捐款平台` 模組 |
| 金流 | **正式串接 LINE Pay Online API**（不是收款連結） |
| 憑證 | 電子發票與捐贈收據**兩種都做，依項目設定** |
| 捐款人 | **不登入、不註冊**，只填姓名與 Email；Email 軟性比對會員僅供標示 |
| 語系 | 繁中（預設）＋英文 |
| 技術選型 | 未定 |

## 3. 後台模組速查　`行 350–436`

```
N. 慈善捐款平台
├── N1 店家管理與 QR Code    店家欄位、store_share_pct、store_slug、QR 產出（PNG/SVG/印刷版 PDF）
├── N2 捐款項目管理          金額選項、目標、project_share_pct、invoice_mode、關聯 CharityProgram
├── N3 捐款紀錄              逐筆檢視、退款、Email 比對會員（僅標示）、異常佇列
├── N4 回饋金結算            店家與項目分開結算、對帳單 + CSV、人工匯款只登記狀態
├── N5 發票與收據管理        補開、作廢、折讓、匯出
├── N6 捐款報表              總覽／依店家／依項目／發票狀況／逐筆明細
└── N7 站台設定              文案 zh/en、四封信樣板、金額上下限、環境切換
```

> 代號用 `N`：`D` 因課程模組 D1–D4 改名 P1–P4 的歷史避用，`M` 易與 Member 混淆。

## 4. 分潤怎麼算　`行 463–516`

```
店家回饋金 = 捐款金額 × store_share_pct
項目撥付金 = 捐款金額 × project_share_pct
俱樂部留存 = 捐款金額 − 店家回饋金 − 項目撥付金
約束：store_share_pct + project_share_pct ≤ 100%
```

四條容易踩到的規則：

1. **兩筆分潤相加、分別入帳**，是兩個不同對象的撥付，N4 產兩份對帳單。
2. **以捐款毛額計算**，不是扣手續費後的淨額；手續費由俱樂部留存吸收。
3. **成立時快照百分比**，事後改設定**不追溯**——對帳單送出去就不能浮動。
4. **無條件捨去至整數元**，尾差歸俱樂部留存；報表合計必須等於逐筆加總。

## 5. 容易搞錯的關係

| 情況 | 正確做法 |
|---|---|
| 掃碼引流的店家 | `DonationStore`（有分潤、有金流）。**不是** `PartnerStore` |
| 給會員折扣的特約店家 | `PartnerStore`（主站 8.4，無金流無分潤）。**不是** `DonationStore` |
| 同一家店兩邊都做 | **各建一筆**，不共用紀錄、不建外鍵 |
| 募款的標的 | `DonationProject` |
| 已執行的公益計畫 | `CharityProgram`（主站 11.2）。`DonationProject` 可關聯它，反向不成立 |
| 受贈公益團體 | `Charity`（主站既有），項目撥付對象直接關聯它 |
| 捐款人是不是會員 | **只用 Email 軟性比對後標示**，不寫入 `Member`、不建關聯欄位、不做歸戶 |
| 捐款主檔放哪 | **擴充主站既有的 `Donation`**，不另建 `DonationOrder`——主站捐款管道已收掉，避免兩份真實來源 |
| 只有 `paid` 才算數 | `created` / `pending` **不得**出現在任何金額統計與分潤計算中 |

## 6. 已知踩雷點

1. **「店家」有兩種、「項目」有兩種**——見上表。這是本專案最大的混淆源，後台介面也必須把名稱區分清楚。
2. **主站已經不做站內捐款與志工報名**（規劃書 v2.1）。看到舊文件寫 Shopify 捐款品項、銀行匯款、物資捐贈、匯款回報表單、志工報名表單，一律視為錯誤。
3. **「官網不接金流」只適用於主站**。本平台正式串 LINE Pay，別把主站的前提套過來。
4. **勸募資格與捐贈收據資格是上線前提，不是一般待確認事項**。未確認前不應開始印製 QR Code。
5. **QR 網址不可攜帶金額或分潤參數**，`store_slug` 只是歸屬標記，且不可由店家編號推導。
6. **冪等性是硬性要求**：同一 `order_no` 重複 Confirm 不得重複入帳、重複開票、重複寄信。
7. **「已扣款但 Confirm 失敗」不可靜默丟棄**，必須進 N3 的異常佇列並主動通知。
8. 網域未定前，主站的導流連結一律留 `.pending-inline` 標記，**不要杜撰網址**。
